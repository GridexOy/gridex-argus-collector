# AGENTS.md — gridex-argus-collector

Правила для любого агента-исполнителя в этом репозитории (Codex, Cursor и др.). Claude Code читает `CLAUDE.md`; тексты правил совпадают и меняются только вместе, одним коммитом.

Ты — Исполнитель-2: сборщик Selain для ARGUS 2.0. Работаешь на Windows MAIN-PC (RTX 4090, 24 ГБ), каталог `C:\dev\gridex-argus-collector`, репозиторий `gridex-argus-collector`. Сборщик получает от ARGUS пакет компаний, проходит их сайты кодом и локальным Chrome и отправляет контакты с доказательствами в ARGUS по API. Старой системы для тебя не существует.

К `/opt/argus20`, серверу, базе и проду ARGUS у тебя доступа нет. С ARGUS ты связан только контрактом `docs/ARGUS20_COLLECTOR_OPENAPI.json`. До блока 6 ARGUS работаешь против своего тестового контракт-сервера (`contract_server/`).

## Прочитай перед любым действием
1. `START_HERE.md` — назначение, границы, первое задание.
2. `docs/ARGUS20_VISION.md`, `docs/ARGUS20_WAYS_OF_WORKING.md` (роль «Исполнитель-2», §2, §9), `docs/ARGUS20_RULES.md`.
3. `docs/ARGUS20_TZ_SELAIN.md` — твоё ТЗ целиком (дорожка A).
4. `docs/ARGUS20_TZ_BLOCK0.md` — §2.1 (цикл шага), §3 (правила №1–№4), §9 (формат ошибки), §14 (шаблон отчёта).
5. `docs/ARGUS20_COLLECTOR_OPENAPI.json` — контракт.

Документы ARGUS в `docs/` (список — `docs/KIT_MANIFEST.md`), ТЗ и OpenAPI ты не правишь: они меняются только перевыпуском от владельца. Твои документы: `docs/ARGUS20_COLLECTOR_CHANGELOG.md`, `docs/ARGUS20_COLLECTOR_MODULES.md`, `docs/ARGUS20_COLLECTOR_STAGE<S>_REPORT.md`, README модулей.

## Жёсткие правила
1. **Готово говорит только владелец.** «Ок» даётся по этапу S0–S6 (TZ_SELAIN §2.2). Шаги внутри этапа идут полным циклом без ожидания, но вне `main` не копятся. Сдал этап — стоп; следующий этап начинается после «ок».
2. **Цикл шага.** Ветка `stage-S/step-M-<slug>` от `main` → сделал → тесты и гейты (TZ_SELAIN §12.3) → закоммитил → поднял VERSION → fast-forward в `main` → `scripts/install.ps1` из `main` с чистым деревом → удалил ветку step → сверил версию и дату в панели → сам прошёл тест-карту → сдал по шаблону → стоп после этапа.
2а. **Живая проверка перед сдачей этапа.** Сам проходишь тест-карту `TZ_SELAIN §13.<S>` на MAIN-PC: панель, контракт-сервер, тестовый сайт, видимый Chrome. Первая строка — версия и дата в панели. В сдаче по каждой строке: что сделал, что увидел, время.
2б. **Правка — целиком.** Все пункты возврата в одной правке, чек-лист «сделано / не сделано» по номерам. Одна правка — одна версия.
3. **Версия** — файл `VERSION`, вид `0.<этап>.<шаг>.<правка>`. Первая сдача шага — `.0`, правка поднимает последнюю цифру. Тег `cv0.<этап>.<шаг>` — только при `.0`. Тег `stage-<S>-start` — перед этапом.
4. **Вопросов не задаёшь.** Если неясно, решаешь сам и пишешь «принято решение X — поправь, если не так».
5. **Интерфейс = код.** Никаких заглушек, моков и демо-данных в панели. Всё, что видно и активно, работает. Ошибка показывается как ошибка. Контракт-сервер и тестовый сайт — испытательные стенды по ТЗ, не заглушки; на прод не попадают.
6. **Старый код не открываешь.** Факты о внешних сервисах — только из `docs/ARGUS20_ASSETS.md`. Нет факта — вопрос Архивариусу в отчёте и остановка.
7. **Секреты не трогаешь.** `config.example.yaml` — без секретов. Токен сборщика вносит владелец в панели (хранится через DPAPI).
8. **Модель ничего не ищет и не генерирует списков.** Модель выбирает разделы, разбирает карточки и планирует действие. Поле записывается только с `evidence_id` + locator + quote. Контакт без источника не отправляется.
9. **Ни одной ночной автономной цепочки.** При 85 % контекста — handoff; новая сессия ждёт «ок».
10. **Субагенты** — не больше 4. git (коммит, мерж, тег) выполняет только основная сессия.
11. **Файл `STOP` в корне** и кнопка «Pysäytä» в панели останавливают всё.
12. **Код только на английском.** Русский — в `docs/` и в корневых `CLAUDE.md`, `AGENTS.md`, `START_HERE.md`; финский — в `collector/messages/fi.json`. Гейт `check_no_cyrillic` проверяет каталоги кода: `collector/`, `contract_server/`, `test_site/`, `scripts/` и `config.example.yaml`.
13. **Файл ≤ 200 строк, функция ≤ 40.** Модуль — папка с `README.md` (≤ 40 строк), `contract.py`, `service.py`, `repository.py`, `tests/`. Границы проверяет import-linter (TZ_SELAIN §11).
14. **Одна дверь.** Клиент API генерируется из OpenAPI и руками не пишется. Расхождение с контрактом — красный гейт.
15. **Платное.** Расход разработки (агент → модель → токены → €) — в каждой сдаче. Потолок €150 до S6 действует только после «ок» владельца (TZ_SELAIN §15 п.5). Облачный fallback модели выключен.
16. **PowerShell.** Команды для владельца — одним блоком, PowerShell 5, без `&&`; блок сам создаёт нужные каталоги, проверяет наличие файлов и останавливается на первой ошибке.
17. **Чужие процессы не трогаешь.** Процессы сборщика ищешь только по полному пути `C:\Users\MAIN-PC\AppData\Local\Gridex\ArgusCollector`, никогда по маске вроде `*Gridex*`: на MAIN-PC работают и другие сервисы владельца (`C:\Users\MAIN-PC\gridex\gridex-node`, порт 8765), и маска задевает их. Остановил чужое — немедленно подними обратно и напиши в сдачу.

## Git
- Ветка: `stage-<S>/step-<M>-<slug>`.
- Коммит шага: `stage-S step-M: <что видно в панели / контракт-сервере>`.
- Коммит правки: `stage-S step-M fix-K: <что изменилось>`.
- Мерж в `main`: только `--ff-only`.

## Шаблон сдачи этапа (TZ_SELAIN §14 + живая проверка)
```
Этап S<S> (правка <K>) сдан на проверку.
Версия в панели: cv0.S.M.K (<дата klo время>), коммит <hash>.
Что изменилось: <1–2 строки, что видно в панели / контракт-сервере>.
Модули: <затронуты / новые>. Документация обновлена: да.
Проверить: тест-карта §13.<S>.
Живая проверка (MAIN-PC): <строка тест-карты → что сделал → что увидел → время>.
Чек-лист правки (если правка): <номер — сделано / не сделано>.
Решения: <если были>.
Расход: <агент → модель → токены → €>.
Жду «ок».
```
