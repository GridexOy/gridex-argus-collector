# ARGUS 2.0 — Видение

**Дата:** 17.09.2026 · **Правка:** 02 · **Владелец:** Игорь · **Статус:** утверждено владельцем как основа

## Одной фразой
Продавец вводит название выставки, уходит пить кофе, возвращается к списку компаний и людей, которым звонить.

## Зачем
Gridex/PRIDEXPO продаёт выставочные стенды в Финляндии и Скандинавии. Перед каждой выставкой нужно знать, кто выставляется и кто в этих компаниях отвечает за выставки и маркетинг. Организаторы публикуют списки поздно и неполно, а ручной сбор занимает дни. ARGUS делает эту работу машиной.

## Пользователь
Пользователь — продавец, не исследователь. Ему не нужны вопросы, методики и критерии. Каждый вопрос системы посреди работы считается дефектом продукта.

## Вход
Обязательно только название выставки. Опционально: год, URL организатора, PDF, список известных компаний. Единственный допустимый вопрос — до старта, если название неоднозначно.

## Что система делает, по порядку
1. **Паспорт события.** Организатор, площадка, даты, цикличность, платформа каталога, число экспонентов по годам. Каждое поле находится в одном из трёх состояний: ищем / нашли + источник / не нашли + что проверено. «Отсутствует» без пояснения — дефект.
2. **Scout.** Те же вопросы параллельно уходят в 4 web-модели: сколько экспонентов ожидается, кто уже заявлен, где лежат списки прошлых лет. Ответы служат только подсказками-URL. Каждый URL открывается, с него снимается снимок, и лишь тогда факт записывается.
3. **Списки участников по годам.** Список лежит в конечном наборе мест: платформа организатора, архив Wayback, PDF плана зала. Система идёт туда детерминированно и читает целиком. Модель читает загруженную страницу; модель никогда не генерирует список.
4. **Один список компаний.** Одна компания занимает одну строку с участиями по годам и приоритетом по кратности (3×/2×/1×). У каждой есть ссылка на источник и сохранённый снимок. Статус берётся только из источника: confirmed / strong_historical / probable / candidate / rejected. Если список текущего года не опубликован, система честно пишет: «реконструкция из прошлых лет».
5. **Люди.** По каждой компании: кто отвечает за выставки, маркетинг, коммуникации, продажи; для малых — директор. Источник — всё, что компания сама опубликовала: сайт, henkilöstö, пресс-релизы, PDF-брошюры и прайсы. LinkedIn не скрейпится. Внешний провайдер работает отдельным каналом с источником на каждый контакт.
6. **Каналы связи со статусом.** published_direct / published_general / catalog_published / inferred / provider_verified / stale. catalog_published — контакт из каталога организатора; он служит стартовой точкой лестницы И7, а роль подтверждается на сайте компании. MX-запись не считается проверкой. Вычисленный адрес никогда не «проверенный». Ценность лида определяется глубиной: 10 компаний с именем и прямым номером лучше 360 без людей.

## Выход
Таблица с фильтрами и экспортом (CSV/XLSX). В ней: компания, участие по годам со статусом и доказательством, приоритет; человек, роль, каналы со статусом, дата, источник. Отдельно показано, что не найдено и почему. Расход прогона показан в евро, настоящий. Результат принимает владелец нажатием; без этого проект не завершён.

## Поведение
- Автопилот — единственный режим. Пересобрать, завершить зависшее, обойти блокировку система должна сама, молча, с записью в лог.
- Первые минуты дают видимый результат: своя база и сайт организатора идут первыми.
- Потолок расхода задаётся один раз при старте. Внутри прогона не задаётся ни одного вопроса; при пробитии потолка — стоп и сообщение.
- Писем система не отправляет. Найти — автоматически, написать — человек.
- Кнопка — обещание: если она есть, она работает. Счётчики не противоречат друг другу.
