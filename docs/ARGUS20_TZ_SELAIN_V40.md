## 1. Контекст: что мы строим и при чём здесь Selain

**Продукт.** ARGUS 2.0 — продавец выставочных стендов (Gridex / PRIDEXPO, Финляндия) вводит название выставки и получает список компаний-экспонентов и людей в них, кому звонить: маркетинг, выставки, коммуникации, продажи, для малых компаний — директор. Каждый человек — с ролью, прямым телефоном и/или почтой, датой и ссылкой на источник. Пользователь — продавец, не исследователь: никаких вопросов и ручных действий посреди работы. Результат он смотрит на `argus.gridex.fi`, вкладка **Soittolista**.

**Эталонный проект сейчас:** «Sähkö–Electricity 2028» — 283 компании, из них с людьми продаж/маркетинга 126, без людей 69 (на 10.10; было 107 на 06.10). Цель чистого прогона: ≥ 75 % компаний с людьми продаж/маркетинга, ≤ 40 без людей, Gold R ≥ 0.75.

**Как сервер ищет людей сам (Kontaktit 3.0, интегрируется на этой неделе):**
C0 каталог организатора → C1 лестница контактных страниц сайта (httpx, без браузера) → C2 серверный Playwright по правилам → C3 Serper people (≤ €1/прогон) → C4 Wayback → C5 PRH (реестр) → **C6 Selain** → C7 платный провайдер (заглушка).

**Что такое Selain.** Программа на MAIN-PC (Windows 11, RTX 4090, Chrome, Ollama с `qwen2.5:14b-instruct`): берёт у сервера пакеты заданий по 8, обходит сайт компании в настоящем Chrome, извлекает людей и каналы, шлёт события и снимки страниц на `/api/collector`. Факт без снимка не принимается. Selain — **последний** канал: только для компаний, где сервер физически не смог (403/WAF, капча, контакты после кликов). Ожидается ≤ 40 компаний из 283.

**Два факта, которые меняют посылки v3.x:**
1. **Финского IP у Selain нет.** Прямой выход MAIN-PC — Россия (СПб), через Hiddify — Германия (Франкфурт). Посылка «Chrome с домашним финским IP обходит WAF» ложная. Selain отличается от серверного C2 только тремя вещами: настоящий Chrome с профилем, бесплатная локальная модель, сайты с кликами.
2. **Сервер после 0.4.24.6 читает статические контактные страницы сам.** Blåkläder (22 человека на `/ota-yhteys`) сервер нашёл без Selain. Таких компаний среди «без людей» было 15 — они ушли серверу.

### 4.1. Шаг 6.1 — снять лишнее (подробно)

Убрать целиком, не выключить флагом:
- модель-навигатор `qwen2.5:7b` и всё, что выбирает следующую ссылку через модель (`walk/decide.py` в части модели, `models/*` для навигации);
- модель зрения `qwen2.5-vl:7b` и скриншоты для модели (`walk/vision.py`, `models/tests/test_images.py` и связанное);
- кэш меню;
- параллельные вызовы модели (пул потоков для `cards`);
- локальный тест панели «Testaa paikallisesti» (кнопка и код), если он не используется в тест-карте владельца;
- `install_model.ps1` ставит только 14b; `OLLAMA_MAX_LOADED_MODELS` не нужен.

Остаётся: правила чтения карточек (`walk/rules.py`, `extraction/text_cards.py`, `extraction/jsonld_people.py`, `extraction/email_pattern.py`), модель 14b **только** для фрагмента страницы, который правила не прочли (окно ≤ 3000 символов, строгий JSON, одна попытка, «спасение» оборванного JSON остаётся).

Принято решение — поправь, если не так: порог «правила не прочли» = на странице класса `contact` найдено 0 людей при ≥ 2 телефонах/почтах в тексте.

### 4.2. Шаг 6.2 — правила ходят

Лестница (детерминированная, та же логика, что серверный C1):
1. Корень → применить K10 (страна/язык): hreflang `fi`, затем переключатель страны/языка, затем пути `/fi/`, `/fi-fi/`, `/en-fi/`; если страна компании ≠ FI (по заданию `company_country`) — K9: страница `locations|addresses|worldwide|offices|contact` → выбрать `Finland|Suomi` по URL/списку, не по редиректу; нет — региональный `Nordic|Scandinavia|Northern Europe`; нет — головной офис с пометкой.
2. Контактные страницы по словарю (приоритет сверху вниз): `yhteystiedot, henkilöstö, henkilökunta, tiimi, johto, myynti, ota yhteyttä, toimipisteet, toimistomme` / `kontakt, personal, medarbetare, kontakta oss` / `contact, team, people, staff, management, sales, offices, about` / `kontakt, ansprechpartner, team` / `kontakt, ansatte, medarbeidere`; плюс `sitemap.xml` по тем же словам; плюс ссылки из футера.
3. На каждой странице: сначала правила (JSON-LD, карточки, текстовые блоки, `tel:`/`mailto:`, шаблон почты K13), потом — при условии §4.1 — модель.
4. K11 правило цели: после страницы — итог; люди продаж/маркетинга с прямым каналом → цель достигнута; дочитать уже найденные ссылки классов `team|henkilöstö|yhteystiedot` ≤ 2; стоп. Иначе — следующая страница лестницы, бюджет страниц ≤ 8, действий ≤ 40, 60 с на компанию мягкий лимит (после — завершить с тем, что есть, `partial`).
5. K12: страница, где контакт = форма с reCAPTCHA/капчей и нет людей/каналов — класс `form`, не `contact`; стоп-признак, в лестнице дальше.
6. K7: люди и каналы — только со страниц домена компании, поддоменов и хоста редиректа (`approved_hosts` из задания сервера, основание `redirect_from_seed`); чужие домены — только как источник, без извлечения людей.
7. Стоп-лист UI-мусора (имена и должности): FI/SV из RULES C2 + EN/DE/NO/LT: `Please Select, Andere Kontaktmöglichkeiten, Teknisk Avdeling, Markedsansvarlig Grossist, Kundeservice, Switchboard, Reception, Vaihde, Asiakaspalvelu` как имя — отбрасывать; как должность без имени — канал компании.
8. Y-tunnus (K14): на каждой своей странице регулярка `Y-tunnus|FO-nummer|Business ID` + `\d{7}-\d` с контрольной цифрой, `FI\d{8}` → `company.business_id` с цитатой (контракт 3.2 поле есть).

Клики допускаются только: переключатель страны/языка, cookie-баннер «hyväksy/accept», аккордеон/«näytä lisää» внутри контактной страницы, вкладки с людьми. Переход по меню — только по ссылке `href`, не по клику.

### 4.3. Шаг 6.3 — одна компания = одна посылка

Сейчас: десятки запросов на компанию (снимок, снимок, событие, событие, heartbeat), каждый со своим seq, отказом и повтором — отсюда sequence_gap, evidence_missing, 3 157 запросов в сутки.

Будет: после обхода сборщик собирает **посылку** — архив `delivery-<job_id>.zip`: `manifest.json` (компания, задание, страницы с URL/sha256/время, люди, каналы, цитаты со span, Y-tunnus, причина остановки, тайминг) + снимки HTML. Один `POST /api/collector/deliveries` (multipart, ≤ 25 МБ). Сервер проверяет всё разом и отвечает одним JSON: `accepted: [...]`, `rejected: [{id, code, field, message}]`, `job_status`. Outbox хранит посылки; повтор посылки идемпотентен по `job_id + run_id`; ≤ 3 повтора при 5xx, затем «Hylätty: palvelinvirhe» с причиной.

Пока сервер не выдал эндпоинт (его шаг — на доске, «Вопросы к другим»), сборщик работает в режиме `delivery.mode: events` (как сейчас), но посылка уже собирается и кладётся в `state/deliveries/` — это и есть проверка шага 6.3 до сервера.

## 5. Спецификация интерфейса (панель ARGUS Selain)

Панель — tkinter, финский, без заглушек. Блоки сверху вниз:

**Yhteys.** `Yhdistetty · viimeksi 14:32:10` зелёным; `Hidas yhteys: 12 s` жёлтым (сокет сообщил timed out, ответ пришёл); `Ei verkkoa: <причина>` красным (connection refused / нет ответа 30 с); `Palvelinvirhe: 503` красным. Одна строка, один источник (транспорт), нигде ниже состояние связи не повторяется. Кнопки: `Yhdistä` (только новый ключ), `Yhdistä uudelleen`.

**Keruu.** Кнопки `Käynnistä · Keskeytä · Pysäytä`. Строка состояния **всегда** говорит, что происходит, одна из:
- `Pysäytetty`
- `Tarkistetaan tehtäviä ARGUSista…`
- `Pyydetään pakettia (0/8)…` / `Pakettia ei saatu: <причина>` (провал claim виден и при непустой очереди)
- `Kerää: <yritys> · <vaihe> · sivu 2/8 · 00:41`
- `Tavoite saavutettu: 3 henkilöä, 4 kanavaa` (3 с, потом следующая компания)
- `Ei tehtäviä jonossa` (сервер отдал 0)

Чекбоксы автозапуска остаются. Кнопки «Testaa paikallisesti» нет (снята в 6.1).

**Löydetty** — таблица людей текущей компании: Nimi (как в HTML-тексте, не капсом из CSS) · Titteli · Rooli (Myynti/Markkinointi/Johto/Muu) · Puhelin · Sähköposti (с пометкой `oletettu:` перед адресом по шаблону) · Lähde. Двойной клик — источник в браузере.

**Jono** — таблица заданий: Yritys · Maa · Vaihe · Henkilöt · Kanavat · Sivut · Kesto · Tila. Tila — словами: `Odottaa`, `Kerää`, `Valmis`, `Osittain valmis · <причина>`, `Hylätty N: <причина>`. Причины отказа сервера — словами по схеме 1.2 (`henkilöltä puuttuu nimi · kenttä email`), не кодами.

**Lähetys** — `Odottaa lähetystä: N · Lähetysvirhe: N (<причина>) · p95 (1 min): 0,8 s`. В режиме посылок: `Lähetys 1/1 · 0,8 s`. Состояние связи здесь не дублируется.

**Resurssit** — как сейчас, минус строки про 7b и VL; `Reititys: säännöt → qwen2.5:14b`.

**Версия** внизу: `cv0.5.1.0 (10.10.2026 klo 14.10) <hash>`.

Правило экрана: чего нет в коде — нет на панели; ошибка — словами; одно состояние — одна строка — один источник.

## 7. Стек

## 9. Контракт с сервером

Текущий: `docs/ARGUS20_COLLECTOR_OPENAPI.json` 3.2, схема событий 1.2 (heartbeat `schema_versions: ["1.1","1.2"]`, `detail` отказа словами).

Нужно от сервера для S6 (пишется на доску в «Вопросы к другим», сервер отвечает там же; до ответа — флаг `events`):

3. Код завершения `goal_reached` в `completion_reason` (контракт 3.3).
4. Автоочередь Selain — только `company_country == event_country` (FI); иностранные — только по кнопке «Etsi Selaimella».

Серверу это — его шаг после 0.4.25 (на доске).
